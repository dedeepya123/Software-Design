# Introduction: Why SOLID Exists

## Core Problem
- Software changes continuously.
- Good designs must accommodate change without becoming fragile.

## Purpose of SOLID
- SOLID is a collection of design principles that help software remain maintainable, extensible, testable, and understandable.

## Relationship to Earlier Phases
- Phase 0 introduced universal design principles such as modularity, cohesion, coupling, encapsulation, and managing change.
- Phase 1 showed how to model systems using objects, classes, relationships, composition, interfaces, and collaboration.
- SOLID builds on those foundations and provides practical guidance for assigning responsibilities and structuring collaborations.

## The Five Principles
- SRP: One responsibility per module/object.
- OCP: Extend behaviour without modifying stable code.
- LSP: Subtypes must be safe replacements for their base types.
- ISP: Keep interfaces focused and relevant.
- DIP: Depend on abstractions rather than concrete implementations.

## Mental Model
- SOLID is not a set of isolated rules.
- It is a framework for helping object-oriented systems evolve gracefully as requirements change.
