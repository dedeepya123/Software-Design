# Open/Closed Principle (OCP)

## Definition
- Software entities should be open for extension but closed for modification.

## Core Idea
- Add new behaviour by creating new components instead of repeatedly editing stable, working code.

## Why OCP Exists
- Every modification introduces the risk of regressions.
- Stable code should remain stable as new features are added.

## How OCP Is Achieved
- Identify what is likely to vary.
- Separate stable and changing parts.
- Use interfaces (contracts) for the varying parts.
- Use polymorphism so different implementations satisfy the same contract.
- Use composition to inject or assemble the required implementation.

## Common Misconceptions
- OCP does not mean "never modify code."
- OCP does not require making everything extensible.
- Design extension points only where change is likely.

## Connection to Previous Lessons
- SRP keeps responsibilities focused.
- Interfaces define contracts.
- Polymorphism allows interchangeable implementations.
- Composition assembles systems from interchangeable parts.
- Together, these principles enable OCP.

## Mental Model
- Stable code is like a house's foundation.
- Variable behaviour is like furniture that can be replaced without rebuilding the house.##
