# How SOLID Principles Work Together

## Core Idea
- SOLID principles are complementary, not independent.
- Together they help software evolve without becoming fragile.

## How They Relate
- SRP: Each component has one clear responsibility.
- OCP: Extend behaviour by adding new implementations instead of modifying stable code.
- LSP: New implementations must honour the behavioural contract.
- ISP: Keep interfaces focused on one cohesive capability.
- DIP: High-level components depend on abstractions rather than concrete implementations.

## Flow of Good Design
1. Identify responsibilities.
2. Separate them into cohesive components.
3. Define clear contracts between components.
4. Allow multiple implementations through polymorphism.
5. Assemble components using composition.
6. Depend on abstractions to reduce coupling.

## Key Insight
- SOLID is not a checklist.
- It is a connected way of reasoning about software design.

## Mental Model
- Design the system so that change stays local.
- When requirements evolve, add or replace specialised components instead of rewriting stable parts of the system.
``` text
  Software changes
        │
        ▼
Need manageable complexity
        │
        ▼
Split into modules
        │
        ▼
Represent concepts as objects
        │
        ▼
Give each object one clear responsibility
        │
        ▼
Define clear contracts (interfaces)
        │
        ▼
Allow multiple implementations (polymorphism)
        │
        ▼
Assemble objects through composition
        │
        ▼
Depend on contracts, not implementations
        │
        ▼
Software becomes easier to extend, test, understand and maintain
```
