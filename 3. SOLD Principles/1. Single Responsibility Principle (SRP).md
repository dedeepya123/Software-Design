# Single Responsibility Principle (SRP)

## Definition
- A class should have one cohesive responsibility.
- Equivalently, it should have one primary reason to change.

## Responsibility
- A responsibility is a cohesive piece of work or a clear purpose that an object owns.

## Reason to Change
- A reason to change is usually a change in one business concern or domain responsibility.
- Different concerns should not be mixed into the same class.

## Key Insights
- SRP is about cohesion, not the number of methods.
- Multiple methods are acceptable if they all support the same responsibility.
- A class with few methods can still violate SRP if those methods belong to different concerns.

## Benefits
- Easier to understand.
- Easier to test.
- Easier to modify.
- Changes remain localised.

## Warning Signs
- God classes.
- Difficult-to-name classes.
- Classes that change for unrelated reasons.

## Connection to Earlier Lessons
- High cohesion naturally leads to SRP.
- SRP supports modularity and managing change.
- SRP encourages collaboration by keeping responsibilities focused.

## Mental Model
- Think of each class as a specialised tool or role.
- Every class should have one clear purpose in the system.
