# Dependency Inversion Principle (DIP)

## Definition
- High-level modules should not depend on low-level modules.
- Both should depend on abstractions.

## Core Idea
- Depend on capabilities (contracts), not concrete implementations.

## High-Level vs Low-Level
- High-level modules express business policies or workflows.
- Low-level modules provide implementation details.

## How DIP Is Achieved
- Define an abstraction that represents the required capability.
- High-level modules depend on the abstraction.
- Low-level implementations also depend on the abstraction by implementing it.
- Compose the system by supplying the required implementation.

## Relationship to Earlier Lessons
- Interfaces provide the abstraction.
- Polymorphism enables interchangeable implementations.
- Composition assembles objects together.
- OCP allows new implementations without modifying stable code.
- LSP ensures implementations honour the abstraction.
- ISP keeps abstractions focused and cohesive.

## DIP vs DI
- DIP is a design principle.
- Dependency Injection is a technique for supplying dependencies.

## Mental Model
- Depend on a standard electrical outlet rather than a specific power station.
- Depend on contracts, not implementations.
