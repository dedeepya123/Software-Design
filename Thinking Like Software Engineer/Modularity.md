# Modularity

## Definition
- A module is a self-contained unit of software responsible for one logical part of a system.

## Why Modularity?
- Large systems are too complex to understand as a whole.
- Breaking them into modules makes them easier to develop, test, maintain, and extend.

## Core Principle
- Divide a large problem into smaller, focused problems.

## Responsibilities
- Every module should have one clear purpose.
- Modules should avoid taking on unrelated responsibilities.

## Boundaries
- Modules should hide their internal implementation.
- Other modules interact only through well-defined interfaces.

## Module Interactions
- Modules should communicate when necessary.
- Interactions should be minimal and well-defined to avoid unnecessary complexity.

## Mental Model
- Modularity manages complexity by organising software into independent, focused units.
