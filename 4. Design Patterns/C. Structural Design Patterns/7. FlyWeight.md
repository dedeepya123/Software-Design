# 7. Flyweight Pattern

## Problem
- Large numbers of similar objects waste memory by storing identical data repeatedly.

## Core Idea
- Separate shared (intrinsic) state from unique (extrinsic) state.
- Store the shared state once and let many objects reference it.

## Recognition Questions
- Are many objects duplicating the same data?
- Can the shared data be made immutable?
- Can unique state be passed separately?
- Will sharing significantly reduce memory usage?

## Intrinsic State
- Shared
- Immutable
- Stored inside the Flyweight

## Extrinsic State
- Unique
- Provided by the client or surrounding context
- Not stored inside the Flyweight

## SOLID Principles
- SRP: Separate shared data from object-specific data.
- OCP: New flyweight types can be added without changing existing ones.

## Comparison
- Singleton: One instance because only one should exist.
- Proxy: Controls access to an object.
- Factory: Creates objects.
- Flyweight: Shares common state among many logical objects.

## Key Insight
- Flyweight minimizes memory by sharing immutable state across many objects.
