# Bridge Pattern

## Problem
- Two dimensions of a system change independently.
- Combining them with inheritance leads to a class explosion.

## Core Idea
- Separate the abstraction from its implementation.
- Connect them using composition instead of inheritance.

## Recognition Questions
- Are there two independent axes of change?
- Would inheritance create many combinations?
- Is one abstraction holding a reference to another abstraction?

## SOLID Principles
- OCP: Add new abstractions or implementations independently.
- DIP: Abstractions depend on abstractions, not concrete implementations.
- SRP: Separate high-level behaviour from low-level implementation.
- Composition over Inheritance: Combine behaviour instead of multiplying subclasses.

## Adapter vs Bridge
- Adapter solves incompatibility between existing interfaces.
- Bridge separates independently varying dimensions from the start.

## Key Insight
- Bridge is about designing for independent evolution, not fixing incompatibility.
