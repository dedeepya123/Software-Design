# Lesson 3: Composite Pattern

## Problem
- Need to represent tree-like part-whole hierarchies.
- Clients should treat individual objects and groups uniformly.

## Core Idea
- Define a common abstraction for both leaf objects and composite objects.
- Composite objects delegate operations to their children recursively.

## Recognition Questions
- Is the structure recursive?
- Can individual objects and groups be treated the same?
- Does one object contain objects of the same abstraction?
- Does recursion naturally appear?

## SOLID Principles
- OCP: New node types can be added without changing clients.
- DIP: Clients depend on the common abstraction.
- LSP: Leaves and composites are interchangeable through the abstraction.
- SRP: Leaves manage themselves; composites manage child aggregation.
- Composition over Inheritance: Recursive composition models the hierarchy.

## Key Insight
- Composite is about modelling recursive part-whole structures so clients don't need to distinguish between individual objects and collections.
