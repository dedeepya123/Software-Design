# Decorator Pattern

## Problem
- Need to add responsibilities dynamically without modifying the original class or creating many subclasses.

## Core Idea
- Wrap an object with another object that implements the same abstraction.
- The wrapper adds behaviour before and/or after delegating to the wrapped object.

## Recognition Questions
- Does a wrapper implement the same interface as the wrapped object?
- Does it forward calls while adding extra work?
- Can multiple wrappers be stacked in different combinations?

## SOLID Principles
- SRP: Each decorator adds one responsibility.
- OCP: New behaviour is added through new decorators, not by modifying existing classes.
- DIP: Both clients and decorators depend on the common abstraction.
- LSP: Decorated and undecorated objects are interchangeable.
- Composition over Inheritance: Behaviour is extended by wrapping, not subclassing.

## Key Insight
- Decorator is about extending behaviour incrementally while keeping the core object unchanged.
