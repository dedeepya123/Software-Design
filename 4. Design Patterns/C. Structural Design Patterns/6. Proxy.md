# Proxy Pattern

## Problem
- Clients should not always access an object directly.
- Access may need to be delayed, protected, monitored, cached, or redirected.

## Core Idea
- Place another object with the same interface in front of the real object.
- The proxy controls access and forwards requests when appropriate.

## Recognition Questions
- Does an object stand in place of another?
- Is access being controlled rather than behaviour extended?
- Is the real object expensive, remote, protected, or lazily initialized?

## Types
- Virtual Proxy: Lazy initialization.
- Protection Proxy: Authorization.
- Remote Proxy: Access to remote objects.
- Caching Proxy: Reuse previous results.
- Logging/Monitoring Proxy: Observe usage.

## SOLID Principles
- SRP: Proxy manages access; real object performs the core work.
- OCP: Add new access policies without changing the real object.
- DIP: Clients depend on the abstraction.
- LSP: Proxy and real object are interchangeable.

## Comparison
- Decorator: Adds behaviour.
- Facade: Simplifies a subsystem.
- Proxy: Controls access to an object.

Key Insight
- Proxy is about controlling access, not changing the object's core responsibility.
