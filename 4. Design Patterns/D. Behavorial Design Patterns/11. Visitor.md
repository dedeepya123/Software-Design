# Visitor Pattern

## Problem
- Object hierarchy is stable, but new operations are added frequently.

## Core Idea
- Move operations out of the classes into visitor objects.
- Objects accept a visitor, which performs the operation.

## Participants
- Element: Defines accept(visitor).
- Concrete Element: Calls the appropriate visitor method.
- Visitor: Declares operations for each element type.
- Concrete Visitor: Implements one specific operation.

## Recognition Questions
- Is the object hierarchy stable?
- Are new operations added often?
- Do I want to avoid modifying every class for each new operation?

## SOLID Principles
- SRP: Objects represent data; visitors represent operations.
- OCP: New operations are added by creating new visitors.
- Tradeoff: Adding new element types requires updating visitors.

## Comparison
- Strategy: Chooses among algorithms.
- Visitor: Adds new operations to an existing hierarchy.

## Key Insight
- Visitor optimizes for systems where element types are stable but behaviors evolve over time.
