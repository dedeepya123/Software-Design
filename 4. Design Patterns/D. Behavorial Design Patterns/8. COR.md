# Chain of Responsibility Pattern

## Problem
- A request may need to be processed by multiple handlers.
- One object should not be responsible for every processing step.

## Core Idea
- Organize handlers into a chain.
- Each handler performs its responsibility and optionally forwards the request to the next handler.

## Participants
- Handler: Defines the common interface and reference to the next handler.
- Concrete Handlers: Perform specific processing.
- Client: Builds the chain and sends the request to the first handler.

## Recognition Questions
- Does a request flow through multiple processing stages?
- Can handlers stop or continue processing?
- Can handlers be added, removed, or reordered?

## SOLID Principles
- SRP: Each handler owns one responsibility.
- OCP: Add new handlers without modifying existing ones.
- DIP: Handlers depend on the Handler abstraction.
- LSP: Any handler can participate in the chain.

## Comparison
- Observer: Broadcasts one event to many listeners.
- Command: Represents an action as an object.
- Chain of Responsibility: Passes one request through a sequence of handlers.

## Key Insight
- Chain of Responsibility decouples the sender of a request from the objects that process it by organizing processing into independent, composable handlers.
