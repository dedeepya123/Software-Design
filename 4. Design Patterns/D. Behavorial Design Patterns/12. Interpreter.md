# Interpreter Pattern

## Problem
- Need to evaluate expressions written in a small language or grammar.

## Core Idea
- Represent each grammar rule as an object.
- Build complex expressions by composing simpler expression objects.

## Participants
- Expression: Defines the interpret(context) interface.
- Terminal Expression: Represents basic grammar rules.
- Non-Terminal Expression: Combines other expressions.

## Recognition Questions
- Am I implementing a small language?
- Can grammar rules become objects?
- Do expressions naturally form a tree?

## SOLID Principles
- SRP: Each expression class implements one grammar rule.
- OCP: Add new grammar rules by adding new expression classes.

## Comparison
- Composite: Organizes tree structures.
- Visitor: Adds operations to a tree.
- Interpreter: Evaluates a tree representing a language.

## Key Insight
- Interpreter models a language by turning grammar rules into composable objects.
