# Mediator Pattern

## Problem
- Many objects communicate directly, creating high coupling and complex dependencies.

## Core Idea
- Introduce a mediator object that coordinates communication.
- Colleagues communicate only with the mediator, not directly with each other.

## Participants
- Mediator: Coordinates interactions.
- Concrete Mediator: Implements the coordination logic.
- Colleagues: Perform their own work and communicate through the mediator.

## Recognition Questions
- Are many objects talking directly to one another?
- Is communication logic spread across many classes?
- Would a central coordinator simplify interactions?

## SOLID Principles
- SRP: Colleagues focus on their own work; mediator manages communication.
- OCP: Add new colleagues without changing existing ones.
- DIP: Colleagues depend on the mediator abstraction.
- LSP: Any mediator implementation can replace another.

## Comparison
- Observer: Broadcasts events to interested listeners.
- Facade: Simplifies access to a subsystem.
- Mediator: Coordinates communication among peer objects.

## Key Insight
- Mediator reduces coupling by moving communication logic into a central coordinator.
