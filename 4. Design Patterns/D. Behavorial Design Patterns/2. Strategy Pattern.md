# Strategy Pattern

## Problem
- One task can be performed using multiple interchangeable algorithms.
- Using large if-else chains makes the code hard to extend and maintain.

## Core Idea
- Encapsulate each algorithm into its own class behind a common interface.
- Let the client choose which algorithm to use.

## Recognition Questions
- Are there multiple ways to accomplish the same task?
- Is behavior selected using conditionals?
- Can algorithms change independently of the main workflow?

## SOLID Principles
- SRP: Each strategy implements one algorithm.
- OCP: Add new strategies without modifying existing code.
- DIP: Clients depend on the strategy abstraction.
- LSP: Any concrete strategy can replace another.

## Comparison
- Factory: Chooses which object to create.
- Strategy: Chooses which algorithm to execute.

## Key Insight
- Strategy separates *what* needs to be done from *how* it is done.
