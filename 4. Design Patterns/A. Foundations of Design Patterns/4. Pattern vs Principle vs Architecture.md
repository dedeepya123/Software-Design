# Pattern vs Principle vs Architecture

## Principles
- General guidelines for good design.
- Examples: SRP, OCP, DIP, low coupling, high cohesion.
- Answer: "How should I think while designing?"

## Design Patterns
- Reusable solutions to recurring design problems.
- Built using design principles.
- Answer: "How should I organise objects to solve this recurring problem?"

## Architecture
- High-level organisation of an entire software system.
- Defines major components, boundaries and communication.
- Answer: "How should the whole system be structured?"

## Framework
- Reusable application infrastructure.
- Often encourages a particular architecture and includes many design patterns.

## Library
- Reusable code that provides specific functionality.
- Called by your application and can internally use design patterns.

## Hierarchy
``` text
Architecture
    ↓
Design Patterns
    ↓
Principles
    ↓
Code
```

## Key Insight
- These concepts complement each other rather than compete.
- Principles guide decisions, patterns solve recurring design problems, and architecture organises the entire system.``
