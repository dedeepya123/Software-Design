# Prototype Pattern

## Problem
- Creating objects repeatedly can be expensive or involve repeated configuration.
- Many new objects differ only slightly from an existing one.

## Core Idea
- Create a new object by cloning an existing object.
- Modify only the parts that need to change.

## Recognition Questions
- Is object creation expensive?
- Do objects share most of their configuration?
- Is there an existing object that is almost what I need?
- Would cloning reduce repeated setup?

## Python Support
- copy.copy() performs a shallow copy.
- copy.deepcopy() performs a deep copy.
- The Prototype pattern is the design concept; copy/copy.deepcopy are implementation mechanisms.

## Benefits
- Reuses existing configuration.
- Avoids repeated initialisation.
- Can improve performance.
- Simplifies creating similar objects.

## Builder vs Prototype
- Builder constructs an object step by step.
- Prototype starts with an existing object and clones it.

## Key Insight
- Prototype is about reusing existing state to avoid unnecessary reconstruction.
