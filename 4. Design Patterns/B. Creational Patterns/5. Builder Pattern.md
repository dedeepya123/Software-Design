# Builder Pattern

## Problem
- Constructing an object becomes difficult because it has many optional parts, validation rules or construction stages.

## Core Idea
- Separate the construction process from the object.
- Build the object gradually and create it only when complete.

## Recognition Questions
- Does the constructor have many parameters?
- Are many parameters optional?
- Does construction occur in multiple stages?
- Is validation required before object creation?
- Would step-by-step configuration improve readability?

## Benefits
- Improves readability.
- Avoids huge constructors.
- Centralises validation.
- Makes complex object construction easier to understand.
- Supports fluent interfaces (optional).

## Builder vs Factory
- Factory focuses on who creates the object.
- Builder focuses on how one complex object is constructed.

## Key Insight
- Builder models the construction process, not just object creation.
