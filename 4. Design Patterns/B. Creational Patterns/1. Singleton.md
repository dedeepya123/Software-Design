# Singleton Pattern

## Problem
- Some concepts in a system should have exactly one shared instance.
- Multiple independent instances would create inconsistent state or waste resources.

## Core Idea
- Ensure only one instance of a class exists.
- Provide controlled access to that shared instance.

## Recognition Questions
- Does this concept naturally represent one shared resource?
- Would multiple instances create inconsistent behaviour?
- Should all parts of the application share the same object?

## Typical Uses
- Application configuration
- Logger
- Connection pool manager
- Model registry

## Python Implementation
- Override __new__() to control object creation.
- Cache the created instance and return it for future requests.

## Advantages
- Prevents duplicate instances.
- Centralises shared state.
- Avoids repeated expensive initialisation.

## Trade-offs
- Introduces global state.
- Can hide dependencies.
- Makes testing harder.
- Can increase coupling if overused.

## Key Insight
- Singleton is appropriate when the domain itself requires one shared instance.
- It should not be used simply because creating one object is convenient.
