# Factory Method (Core Idea)

## Problem
- Clients often become responsible for creating concrete objects.
- As the number of implementations grows, clients become tightly coupled to concrete classes.

## Core Idea
- Separate object creation from object usage.
- Delegate creation to a specialised factory.

## Recognition Questions
- Does the client instantiate many concrete classes?
- Does object creation vary frequently?
- Should the client know the implementation details?
- Is construction logic becoming complex?

## Benefits
- Reduces coupling.
- Centralises creation logic.
- Keeps client code focused on its primary responsibility.
- Makes it easier to replace implementations.

## Relationship to SOLID
- SRP: Client uses objects; factory creates them.
- DIP: Client depends on abstractions rather than concrete implementations.

## Key Insight
- Factory is not about hiding constructors.
- Factory is about assigning the responsibility of object creation to the right place.
