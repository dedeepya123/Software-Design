# Abstract Factory Pattern

## Problem
- Some systems require multiple related objects that are designed to work together.
- Creating these objects independently can lead to incompatible combinations.

## Core Idea
- Provide an interface for creating families of related objects.
- Ensure all created objects belong to the same compatible family.

## Recognition Questions
- Am I creating multiple related objects?
- Should these objects always be compatible?
- Does switching one implementation require switching all related implementations?

## Examples
- Windows UI components
- macOS UI components
- CPU backend components
- GPU backend components
- Cloud provider implementations

## Factory Method vs Abstract Factory
- Factory Method creates one product.
- Abstract Factory creates a family of related products.

## Relationship to SOLID
- SRP: Client uses objects; factory creates them.
- DIP: Client depends on abstract factory interfaces.
- OCP: New product families are added through new concrete factories.

## Key Insight
- Abstract Factory is about preserving compatibility across related objects, not simply creating multiple objects.
